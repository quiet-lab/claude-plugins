# Плагин rm-work-allow

Снимает запрос разрешения на удаление файлов, когда все удаляемые пути лежат
внутри `~/work`. Claude Code проверяет `rm` и `rmdir` отдельно от правил
разрешений и режима `bypassPermissions`: запрос вроде «Dangerous rm operation
detected … target cannot be statically resolved» не снимают ни правило
`allow`, ни решение `allow` хука `PreToolUse`. Его снимает решение `allow`
хука `PermissionRequest`; этот плагин такой хук и поставляет.

## Условие allow

Хук `hooks/rm-work-allow.py` на событии `PermissionRequest` для инструмента
`Bash` возвращает `{"hookSpecificOutput": {"hookEventName": "PermissionRequest",
"decision": {"behavior": "allow"}}}` только когда выполнено всё:

- режим сессии `bypassPermissions` (в других режимах запрос может быть вызван
  не удалением, а `allow` одобрил бы всю команду);
- в команде есть вызов `rm` или `rmdir` (`rm`, `\rm`, `"rm"`, `/bin/rm`,
  `/usr/bin/rm`);
- каждая цель каждого вызова после раскрытия `~` (только свой `HOME`) и
  разрешения `..` и символических ссылок (`realpath`) лежит внутри `$HOME/work`
  на глубине не меньше двух компонентов: `~/work/a/b` разрешается, а сам
  `~/work`, `~/work/a` и шаблоны `~/work/*`, `~/work/a/*` — нет;
- шаблон (`*`, `?`, `[`) стоит только в последнем компоненте пути, а каталог,
  в котором он раскрывается, удовлетворяет условию выше: `~/work/a/b/*`
  разрешается;
- относительные пути вычисляются от `cwd` из входа хука; если в команде есть
  `cd`, `pushd` или `popd`, относительные цели решения не получают;
- команда разобрана целиком (слова, кавычки, операторы `;`, `&&`, `||`, `|`,
  `&`, переводы строк, подоболочки, перенаправления): составная команда
  допускается, если каждый вызов `rm`/`rmdir` удовлетворяет условиям;
- опции `rm` только из `-f -r -R -d -v -i -I`, `--force --recursive --verbose
  --dir --one-file-system --preserve-root --interactive` и `--`.

## Что не разрешается

Хук завершается с кодом 0 и пустым выводом (показывается обычный запрос) при
любом из: переменные и подстановка команд (`$`, обратные кавычки), фигурные
раскрытия, `eval`, `xargs`, `find`, `sudo`, `env`, `command`, `bash -c` и подобные
обёртки (список — `BLOCKED_COMMANDS` в сценарии), слово `rm` среди аргументов
другой команды (`git rm`), присваивание, `export`, `alias`, определение функции,
`here-document`, подстановка процессов, `for` и `case`, любая ошибка разбора,
битый или неожиданный вход, не `Bash`, иной режим, цель вне `~/work`. `deny`
хук не возвращает никогда.

Псевдонимы и функции оболочки пользователя хук не знает: он различает `rm` по
имени команды.

## Журнал

Каждое вынесенное `allow` пишется строкой JSON в
`${XDG_STATE_HOME:-~/.local/state}/rm-work-allow/allow.log`: время, `cwd`,
команда. Если записать журнал не удалось, решения нет.

## Установка

Минимальная версия Python — 3.9, зависимостей нет.

```sh
claude plugin marketplace add quiet-lab/claude-plugins
claude plugin install rm-work-allow@quiet-lab
```

## Проверка

```sh
python3 -I -m unittest discover -s plugins/rm-work-allow/hooks/tests
```
